# Notes

## Confirmed decisions

- The initial measurable engineering budget is defined in `reports/technical-constraints.md`.
- Default TraceDeck persistent storage is capped at 1 GiB, with a 1.25 GiB total working-disk ceiling.
- Capture overhead is limited to 100 ms p95 per synchronous hook and 300 ms p95 per Codex turn.
- The TraceDeck background service is limited to 150 MiB RSS p95 and 250 MiB maximum.
- Capacity management is automatic and visible: oldest completed sessions are pruned at the high-water mark, and every pruning or data-loss event is surfaced locally.
- The MVP supports Windows 11 first and uses supported Codex lifecycle hooks as its primary passive integration interface.
- The one-time installer merges TraceDeck handlers into the user-level Codex hook configuration, preserves existing handlers, creates a backup, and provides an idempotent uninstall. Starting the dashboard remains one command after installation.
- Hook invocations write one bounded event file through temporary-file plus atomic-rename semantics. The collector drains this spool into SQLite, so capture does not depend on the dashboard already running.
- `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`, and `SessionEnd` are the only required MVP hooks. TraceDeck does not install permission or policy hooks.
- A `Stop` event may provide the final assistant message, but it does not provide semantic task success. Dashboard counts use lifecycle states: completed, failed, interrupted, partial, and unknown.
- Hook events do not guarantee token usage. Token fields remain null unless a version-matched local source supplies exact usage. Unknown token values are never converted to zero.
- The transcript path exposed to hooks is a reconciliation fallback, not a stable primary API. Parsers are selected by observed Codex version and must fail closed to `unsupported_format` without blocking capture.
- App Server is a documented client protocol with rich turn, item, and token events, but it is not used as a passive MVP collector because no supported attachment path to already-running host sessions has been established.
- The schema includes `cache_write_input_tokens` in addition to input, cached input, output, reasoning output, and total tokens because the current generated App Server schema exposes that field.
- Source timestamps are not guaranteed by hook input. TraceDeck records `observed_at` and labels observer-derived timestamps and durations explicitly.
- Hosted or specialized tools that bypass local tool hooks are not fabricated. The UI reports tool-coverage limitations.
- Raw tool responses are received only when Codex supplies them to `PostToolUse`; they are bounded, inspected only for status/error normalization, and never persisted.
- One-time installation plus `python -m tracedeck` is the MVP startup contract; silently modifying Codex configuration on every start is not allowed.
- Phase 2 collector and persistence packets are implemented. Transcript reconciliation intentionally supports only the sanitized TraceDeck fixture contract until a consented real Codex transcript establishes stable semantics; unknown records remain `unsupported_format` and usage fields remain nullable.
- A consented local Codex 0.152.0 session confirmed the JSONL envelope shape (`session_meta`, `turn_context`, `event_msg`). The versioned 0.152.x adapter accepts only `event_msg`/`token_count` `info.last_token_usage` as per-turn usage; it ignores cumulative `total_token_usage` rather than deriving deltas.
- Transcript reconciliation must run when a hook supplies a transcript path even if hook payloads omit `codex_version`; the version-gated adapter detects `cli_version` from the transcript metadata.
- Codex CLI was updated to 0.152.0 for live compatibility validation. After the reconciliation-gating fix, a read-only smoke turn stored exact usage with `usage_source=transcript:codex-0.152.x` and `total_tokens=18077`.
- P4.4 packaging and release validation is intentionally deferred until the planned dashboard design update is complete.
- Dashboard follow-up scope is approved: Analytics and bounded local CSV export are included in the next release scope.
- Dashboard times are displayed in the user's local timezone; observer time and ingestion time remain distinct, and unavailable Codex source timestamps stay null.
- Canonical MCP server/tool attribution is approved from hook names such as `mcp__server__tool`; plugin ownership attribution remains `unknown`/`unsupported` for MVP unless a future authoritative passive source is established.
- Active CPU/RSS, physical disk-pressure, and packet-level outbound checks remain isolated release-validation activities and do not block implementation of the dashboard follow-up packets.

General statistics and trends are the default analysis surface; individual prompts/responses are accessed only through bounded search, pagination, sampling, or explicit drill-down. Default API payloads must not load all raw prompt text.

Imported content uses existing redaction/truncation rules, exact `last_token_usage` snapshots only, and explicit `transcript:desktop` source markers. Import is read-only, idempotent through normalized session/turn keys plus a local file manifest, and skips raw tool-call outputs.
- 2026-09-02 P5.1 state contract: the read-only health API classifies collector state as healthy, empty, partial, stale, capture_disabled, setup_required, degraded, or unavailable, with hook readiness and a bounded next action. The dashboard keeps last-known data visible during refresh failures and records the last successful refresh locally.
- 2026-09-02 P5.2 detail contract: nullable duration and usage values render as unavailable while known zero remains zero; usage keeps source/quality text; redaction/truncation markers remain visible. Turn completion is labeled Completed rather than semantic success, and detail tabs/charts expose equivalent keyboard and assistive-text paths.
- 2026-09-02 P5.3 responsive contract: History keeps a semantic table at desktop widths with sticky filters and right-aligned numeric columns; below 600 px, rows become compact labeled cards without horizontal overflow. Started/model/status/tokens/duration remain visible, while tool count stays available through detail.
- 2026-09-02 P5.4 navigation contract: the local dashboard exposes History, Detail, Analytics, and Setup/Status as client-side views. Attention states remain above the data cards; Setup/Status reads health and hook readiness; `/`, `f`, `Esc`, and `Enter` provide keyboard flows without intercepting editable fields.
- 2026-09-02 P6.1 time/retention contract: timestamps remain UTC with millisecond precision in storage; the API declares browser-local display, inclusive start and inclusive-day end semantics, and preserves unknown timestamps. Hook-derived times are labeled observer time; the approved desktop source is labeled source event time. Completed-session pruning records count, ended-at range, reason, and target locally; active sessions and sessions without a known end time are protected.
- 2026-09-02 P6.2 History query contract: `/api/turns` keeps bounded search/model/lifecycle/tool/known-coverage/pagination parameters and adds bounded token/duration ranges. Date filters require ISO dates, use known `started_at` only, include the selected end day through an exclusive next-day boundary, reject reversed ranges, and return active filter/timezone metadata. Unknown metrics never match known numeric ranges.
- 2026-09-02 P6.3 Analytics contract: analytics accepts the P6.1 date semantics, filters only known `started_at` values when a range is active, and returns `no_data`, `token_unavailable`, `partial`, or `ready`. Token trend and heavy-turn data use known tokens only; known zero remains zero and unavailable token coverage is never coerced to zero.
- 2026-09-02 P7.1 attribution contract: only an exact three-part `mcp__server__tool` hook name yields `mcp_server`, `mcp_tool`, and `hook:canonical_tool_name`; malformed and regular local tool names remain nullable. The original bounded `tool_name` is preserved, hosted tools remain outside local hook coverage, and no plugin ownership inference is added.
- 2026-09-02 scope decision: S7.2 plugin ownership source investigation is deferred at the user's request. Plugin ownership stays unsupported/unknown; no plugin schema, config lookup, App Server dependency, or UI field is authorized in the current release.
- 2026-09-02 refresh contract: the dashboard Refresh action calls the loopback-only `POST /api/refresh`, which reruns the bounded idempotent desktop import and drains the local hook spool before reloading summary, Analytics, health, and History data.

- 2026-09-02 normalized message decision: user and final assistant text are linked through `messages` and `turn_messages`; the shared compressed content store deduplicates identical content across turns.
